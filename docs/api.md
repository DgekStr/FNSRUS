# HTTP API

Базовый адрес в локальной сети: `http://192.168.0.45`.
Все POST-запросы передают JSON-объект с `Content-Type: application/json`.
Токен не требуется. API разрешён только для доверенной сети.

## POST /api/check

Полная проверка контрагента с расширенными проверками upstream по умолчанию.
Строка из 10/12/13/15 цифр направляется на проверку ИНН/ОГРН. Текстовый ввод
автоматически направляется на поиск по названию. Цифровая строка другой длины
отклоняется. Для поиска передавайте название компании минимум из двух символов.

```json
{"identifier":"7707083893"}
```

Для проверки `identifier` — строка: ИНН 10/12 цифр либо ОГРН 13/15 цифр.
Нельзя передавать номер как JSON-число: ведущие нули должны сохраняться.

Успешный ответ проверки: HTTP 200, полный JSON инструмента `check_contractor`,
без транспортной MCP-обёртки. Поля не удаляются и не переименовываются:

```json
{
  "identifier": "7707083893",
  "identifier_type": "inn",
  "inn": "7707083893",
  "ogrn": "1027700132195",
  "card": {},
  "legal_status": {},
  "risks": {},
  "verdict_action": "manual_review_required",
  "recommendations": [],
  "sources": {},
  "tier": "open",
  "checked_at": "2026-10-13T10:00:00Z"
}
```

Это сокращённый пример структуры, не полный отчёт и не утверждение о компании.
Пустые поля обозначаются `null`, пустыми массивами или объектами — так, как
их вернул upstream. Для оценки полноты смотрите `risks.coverage`,
`risks.errors`, `legal_status.warnings` и `sources`.

Вердикты:

| Значение | Отображение | Цвет |
| --- | --- | --- |
| `safe_to_proceed` | Можно работать | Зелёный |
| `manual_review_required` | Требуется проверка | Жёлтый |
| `high_risk_do_not_proceed` | Высокий риск | Красный |
| `impossible_contractor_defunct` | Контрагент прекратил деятельность | Красный |

## POST /api/search

Поиск юрлиц по названию в локальном FTS5-индексе OpenSanctions `ru_egrul`.
Если этот индекс ещё не импортирован, используется MCP `mcp-egrul`.

```json
{"query":"сбер"}
```

Успешный ответ содержит не более 50 совпадений. Каждый элемент имеет только
поля `name`, `inn` и `city`; город берётся из адреса, а если его нельзя
выделить — показывается начало адреса (до 30 символов) или `—`.
Для OpenSanctions-источника ответ также включает `source`, `dataset`,
`snapshot_date`, `last_source_change` и `license`; UI показывает эти сведения
и ссылку на источник.

```json
{
  "results": [
    {"name":"ПАО Сбербанк","inn":"7707083893","city":"Москва"}
  ],
  "truncated": false
}
```

`truncated: true` означает, что показаны первые 50 результатов и запрос нужно
уточнить. Пустой массив означает, что совпадений нет. Если официальный снимок
OpenSanctions и fallback-индекс `mcp-egrul` не импортированы, API возвращает
отдельную ошибку готовности базы.

## POST /api/tools/{tool_name}

Вызов одного из семи инструментов. Тело содержит параметры **напрямую**,
без вложенного объекта `arguments`.

| Инструмент | Основные параметры | Назначение |
| --- | --- | --- |
| `check_contractor` | `identifier` | Полный отчёт и вердикт |
| `check_inn` | `inn` | Карточка по ИНН |
| `check_ogrn` | `ogrn` | Карточка по ОГРН / ОГРНИП |
| `get_legal_status` | `inn` или `ogrn` | Юридический статус |
| `get_okveds` | `inn` или `ogrn` | Сведения об ОКВЭД |
| `get_directors_history` | `inn` | Руководитель и доступные сведения об истории |
| `check_for_red_flags` | `inn` | Проверки рисков |

Все идентификаторы — строки. Реальная JSON Schema проверяется по описанию
инструмента, полученному от установленного MCP-сервера 0.1.12. Дополнительные
параметры допустимы только когда их поддерживает upstream.

```bash
curl -s http://192.168.0.45/api/tools/check_ogrn \
  -H 'Content-Type: application/json' -d '{"ogrn":"1027700132195"}'

curl -s http://192.168.0.45/api/tools/get_legal_status \
  -H 'Content-Type: application/json' -d '{"inn":"7707083893"}'
```

## Ошибки

```json
{
  "error": "rate_limit",
  "message": "Превышен лимит, попробуйте через минуту."
}
```

Поле `error` — стабильный технический код; `message` — русское пояснение.
В некоторых случаях присутствует `details` от upstream.

| HTTP | Причина |
| --- | --- |
| 400 | Неверный ИНН / ОГРН, в том числе контрольная цифра |
| 403 | Запрос с другого сайта или настройки вызваны не из LAN |
| 404 | Неизвестный инструмент или контрагент не найден |
| 409 | Уже выполняется другая проверка |
| 413 | Тело запроса больше 1 МБ |
| 422 | Некорректный JSON, формат или схема параметров |
| 429 | Превышен лимит; заголовок `Retry-After: 60` |
| 502 | Подпроцесс завершился с ошибкой / некорректный ответ |
| 503 | Обязательный источник недоступен или база ЕГРЮЛ не загружена |
| 504 | Таймаут вызова MCP, 50 секунд |

Поиск отвечает HTTP 503 с сообщением «Поиск по названию временно недоступен,
введите ИНН» при сбое MCP-сервера. Пока OpenSanctions импортирует снимок,
возвращается код `search_import_in_progress`; если обе базы пусты — отдельная
ошибка готовности. Ни одно из этих состояний не означает, что компания отсутствует.
После завершения импорта до ручной публикации поиск возвращает HTTP 503 с кодом
`search_import_ready_to_publish`.

Частичный агрегированный отчёт может иметь HTTP 200, но
`verdict_action: manual_review_required`. Ошибка необязательного источника
попадает в отчёт, а не маскируется сообщением «рисков нет».

Если ЕГРЮЛ вернул запись без валидного ИНН, API отвечает HTTP 503 с кодом
`invalid_source_data` и предлагает проверить номер или выписку. Такой ответ
не подтверждает, что компания существует или отсутствует. HTTP 404 используется
только когда upstream явно сообщает, что контрагент не найден.

## Настройки API-ФНС

- `GET /api/settings/api-fns`: только `configured`, `enabled`, `verified_at`, `methods`;
  ключ или его часть никогда не возвращается.
- `POST /api/settings/api-fns`: `{"api_key":"<новый ключ>","enabled":true}`;
  проверка через `stat`, затем атомарное сохранение. Без `api_key` меняется включение.
- `POST /api/settings/api-fns/test`: проверить сохранённый ключ через `stat`.
- `DELETE /api/settings/api-fns`: удалить ключ и отключить интеграцию.
- `GET /api/settings/opensanctions`: LAN-only статус импорта, прогресс, средний темп и ETA.
- `GET /api/settings/opensanctions/update-check`: сравнить published version с upstream `index.json`.
- `POST /api/settings/opensanctions/import`: запустить импорт строго указанного `expected_version`.
- `POST /api/settings/opensanctions/publish`: опубликовать готовую staging-базу. Требует `{}` и `X-FNS-Settings: 1`.

Импорт запускается только после сверки версий. Запрос
`POST /api/settings/opensanctions/import` принимает
`{"expected_version":"<версия из update-check>"}`; сервер повторно получает
upstream index и отклоняет устаревший `expected_version` с HTTP 409. Если новая
версия уже опубликована, downgrade не разрешается. Активный systemd unit, статус
импорта и shared file lock блокируют повторный запуск; успешный ответ HTTP 202
означает, что version-scoped unit принят systemd.

Статус OpenSanctions обновляется контрольными точками импорта. Средняя скорость и
ETA рассчитываются по нескольким последним обновлениям; до накопления данных ETA
не показывается. Состояние `ready_to_publish` означает, что поток проверен по
размеру, SHA-1 и числу записей, FTS5 построен, а staging-БД прошла integrity check.
Кнопка публикации в настройках дополнительно проверяет metadata и SQLite quick check,
после чего атомарно заменяет активную базу. До готовности endpoint отвечает HTTP 409;
при ошибке проверки HTTP 422, активная база при этом не заменяется.

В `api_key` можно передать сам ключ (8-256 символов) или регистрационную ссылку
`http://api-fns.ru/api/stat?key=<ключ>` / HTTPS-вариант (до 1024 символов).
Из ссылки извлекается единственный параметр `key`; адрес не открывается.
Проверка выполняется фиксированным HTTPS POST, при HTTP 401/403 повторяется
документированным HTTPS GET; параметры URL удаляются из журналов приложения.
Сохраняется только ключ. Поле `Статус` в ответе `stat` необязательно, если
присутствуют даты действия и непустая статистика методов.
Чужой домен, другой путь и повторяющийся параметр `key` отклоняются с HTTP 422.

Для изменения настроек нужны `Content-Type: application/json` и `X-FNS-Settings: 1`.
Запросы с другого Origin запрещены. Это защита от межсайтовой записи, не авторизация:
настройки предназначены только для доверенной локальной сети. Внешний доступ
требует HTTPS и авторизации. Не передавайте ключ в URL или в чат.
Все маршруты `/api/settings/*` также разрешены только для адресов из
`FNS_SETTINGS_LAN_NETWORKS` (по умолчанию `192.168.0.0/24`, внутренний NAT-шлюз
`10.1.17.6/32` и loopback).
Внешний адрес получает HTTP 403 с кодом `local_network_only`; интерфейс показывает
модальное окно с анимацией и не открывает форму настроек.

Когда интеграция включена, `/api/check` и `/api/tools/check_contractor` добавляют
`api_fns: {egr, check, errors}`. Ключ маскируется даже при отражении поставщиком.
При отсутствии API-ключа прежний JSON-контракт не меняется.
Остальные MCP-инструменты не используют платный API. Покрытие семи проверок
увеличивается только по однозначным результатам; отсутствие отрицательного
фактора не считается подтверждением отсутствия риска. Ошибка одного поставщика
не удаляет доступную карточку другого.

## Служебные маршруты

- `GET /` — русскоязычный интерфейс.
- `GET /static/...` — локальные ресурсы, в production напрямую через Nginx.
- `GET /healthz` — `{"status":"ok"}`; проверяет HTTP-приложение, не все источники.
- `GET /explorer/` — перенаправление на новый интерфейс для старых закладок.

Ограничение обвязки — 10 вызовов в минуту для всех пользователей одного
процесса. Запускайте один worker: несколько workers умножат этот локальный лимит.
Внешние источники дополнительно применяют собственные ограничения на IP.
